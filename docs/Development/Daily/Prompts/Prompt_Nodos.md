Okay vale. Me quiero asegurar de que todo lo que hemos pensado está implementado tal cual como quiero. Por el momento vamos a reformar la parte del Firmware que es la última que debemos actualizar. En este caso me gustaría continuar con la idea de que el Nodo es una Interfaz Abstracta que luego hace que se cree un Nodo_Actuador y un Nodo_Sensor, así como un Nodo_Gateway. En este caso el Nodo_Actuador y el Sensor tienen acceso a SystemContext dado que es la capa de Orquestación del sistema. El actuador tiene habilitado el protocolo por ESP-Now y el Ejecutor, pero no tiene acceso al Módulo de Sensores. El de Sensores tiene acceso a protocolo, systemcontext y sensormanager pero no tiene acceso a ejecutor. El Nodo Gateway tiene acceso a todo. De esta forma si queremos implementar un nuevo nodo_sensor es tan simple como subir la clase, configurar los parámetos en la inicialización del main y ponerlo a funcionar. Esta es la primera decisión. El main deberá ser siempre lo más limpio posible. El nodo es sólo la última capa de implementación que simplifica todo. Para ello es necesario seguir implementando el sistema de Callbacks entre ProtocolEngine y SystemContext, pero actualizarlo y adaptarlo a todo tipo de mensajes y comandos. Luego ya cada Nodo tendrá unos comandos específicos que son los que se activarán para asegurar que no puede hacer funciones que no le corresponden. Tendríamos que modificar el ProtocolEngine e introducir Callbacks específicos para cada tipo de Comando en el sistema para saber cómo gestionarlo y así tener más separadas las distintas respuestas a cada problema. De esta forma me gustaría que refactorizases eso para mantener los principios. En este caso desde la Clase Nodo se gestiona la activación y desactivación de funciones. La inicialización de pines y de las MAC necesarias se pasan a través del main, para asegurarse de que siempre están definidas.
