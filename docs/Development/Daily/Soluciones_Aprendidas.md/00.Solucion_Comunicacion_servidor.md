## 01-Comunicación y mensajes estandarizados

### Problema: Cómo puedo hacer para conectar de forma fiable y estandarizada los mensajes del frontend con el backend y con la Raspberry Pi.

### Solución

1. Aprovechar los schemas de DemeterProtocol y añadirles una cabecera de tipo para identificar el mensaje con un string
    1. Permite que el servidor, backend y Raspberry aprovechen Python para discriminar el tipo de mensaje y procesarlo correctamente
    2. No afecta a la codificación en binario de los mensajes dado que ese tipo simplemente se ignora en el proceso de codificación

### Cosas aprendidas

1. Pydantic tiene una función que permite crear un TypeAdapter que permite validar y serializar/deserializar objetos de forma eficiente, sin tener que crear una función para cada uno. Quizás tiene lo mismo para crear los mensajes en binario.

## 02-Comunicación Frontend<->Backend y Backend<->Raspberry Pi

### Problema

1. Cómo puedo hacer para que el servidor y el backend se comuniquen entre sí y lo mismo con backend y Raspberry. Puedo usar Websocket y/o HTTP para los dos, no sé cuál.

### Solución

1. Usar HTTP para Frontend<->Backend y Websocket para Backend<->Raspberry Pi
    1. HTTP es ideal para enviar comandos hacia la Raspberry dado que sólo se hacen peticiones al servidor cuándo enviamos el comando. No es necesario tener una conexión abierta constantemente.
    2. Websocket es ideal para recibir comandos desde la Raspberry dado que permite tener una conexión abierta constantemente y recibir mensajes en tiempo real.

### Cosas aprendidas

1. Es importante saber usar cada protocolo según el momento para no hacer overengineering
